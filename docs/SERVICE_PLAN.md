# Book to Podcast 服务化方案

## 🎯 目标

将图书转播客 Skill 服务化，提供 Web 界面，支持用户：
- 上传 PDF 文件
- 查看处理进度
- 试听生成的播客
- 下载播客音频

## 🛠️ 技术栈选型

### 前端
| 组件 | 技术 | 理由 |
|------|------|------|
| 框架 | Vue 3 + Vite | 轻量、快速、GitHub Pages 友好 |
| UI | Tailwind CSS | 简洁美观，无需额外组件库 |
| 播放器 | Howler.js | 成熟的音频播放库 |
| 状态管理 | Pinia | Vue 3 官方推荐 |

### 后端
| 组件 | 技术 | 理由 |
|------|------|------|
| 框架 | FastAPI | 高性能、异步、自动文档 |
| 任务队列 | Celery + Redis 或 asyncio | 支持异步任务处理 |
| 数据库 | SQLite | 轻量、无需额外服务 |
| 文件存储 | 本地文件系统 | 简单直接 |

### 部署
| 层级 | 方案 | 说明 |
|------|------|------|
| 前端 | GitHub Pages | 免费、自动部署 |
| 后端 | Railway / Render / VPS | 可选多种方案 |

## ❓ 需要确认的问题

1. **部署方案**
   - A) 仅前端部署 GitHub Pages，后端需用户自行部署
   - B) 全栈部署到 VPS/云服务器（需要服务器成本）
   - C) 后端部署到 Serverless（Vercel/Render 免费套餐）

2. **API Key 管理**
   - A) 用户每次输入（无存储）
   - B) 浏览器本地存储（方便但有安全风险）
   - C) 服务端加密存储

3. **文件存储**
   - A) 临时存储（处理完成后自动清理）
   - B) 持久存储（需要空间管理）

4. **MVP 范围**
   - A) 基础版：上传 → 处理 → 试听 → 下载
   - B) 增强版：+ 历史记录、多语言支持、自定义主持人
